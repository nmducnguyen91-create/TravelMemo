# 05 — Database specification
SQLite, foreign keys per connection, migration ledger, UUID text IDs, UTC ISO timestamps plus local date/timezone. Parameterized queries. Use specs/schema-v1.sql as proposed baseline; review before adopting migration. No modification of released migrations.
Tables: profiles, companions, trips, trip_companions, geo_regions, geo_region_versions, places, visits, visit_regions, passports, stamp_templates, passport_stamps, media_assets, journal_entries, backup_history, settings. Future routes/route_points, wishlist, expenses, tags and collections require new migrations. Media paths relative; original photos untouched. Coverage uses distinct region IDs for selected version; historical mapping derived from preserved coordinates, never overwrite old boundaries. Unique stamp key passport/visit/category/region key; transaction for visit and required stamp when passport module enabled. Backfill earlier confirmed visits idempotently. Soft delete and restore recalculate derived state. Backup manifest includes schema/app version, file hashes, size and creation date.

Migrations live in src/database/migrations (0001 = specs/schema-v1.sql, 0002 app columns + default profile/passports, 0003 indexes). The runner records a checksum per migration and refuses edited, missing or newer migrations.
